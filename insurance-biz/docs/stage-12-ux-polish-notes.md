## 一、投保页的 5 步空表单

### 问题

> "这个投保流程好像只是一个演示版本，没有实际的功能"

### 原来

```
① 保费试算  ② 客户告知  ③ 健康告知  ④ 保单信息  ⑤ 确认支付
   真空表单     空文案       空文案       空文案       真的
```

点 5 次「下一步」，只有第 1 步和第 5 步有东西发生，中间三步什么都没做。

### 现在

压成 3 步，中间那一步换成真内容：

```
① 保费试算          ② 确认投保              ③ 支付完成
 填被保人信息          产品 / 险种 / 被保人
 试算 → 年保费        保额 / 医保 / 报价有效期
 逐行算式             每项系数与算式
                    ☐ 已阅读条款（必勾）
                    ☐ 健康告知声明（必勾）
                    [确认并支付]
```

中间那一步是真数据：

| 内容 | 来源 |
|---|---|
| 被保人参数 | 试算落库的 `request_params` 快照 |
| 应付保费 + 系数 | 试算结果 `breakdown` |
| 两项声明 | 不勾选 → 支付按钮禁用 |

两个细节：

- **改了试算参数，两项声明自动重置** —— 换了保额，"已阅读条款"就不该继续有效
- **没试算就不能进下一步** —— 避免用户没看到价格就走到支付

## 二、刷新后一个气泡变成三个

### 问题

实时流里一个回答是一个气泡，但刷新页面后变成 3 个碎气泡。

### 原因

模型一轮里的实际消息序列：

```
user:      我想咨询「人保小学童2号」…
assistant: 我来帮您查询这款产品的保障内容和投保须知。先确认产品信息。
assistant: 找到这款产品了，我来查询它的条款细节。
assistant: # 人保小学童2号Pro学平险 …（最终回答 1474 字）
```

中间两条是"工具调用前的那句话"。**实时流把它们拼进同一个气泡**，
但 `chat_history` 是逐条读 checkpoint 的，于是变成 3 个气泡。

### 修法

在 `ChatService.chat_history()` 里把**连续的 assistant 消息合并成一条**：

```python
if role == "assistant" and messages and messages[-1].role == "assistant":
    previous = messages[-1]
    previous.content = f"{previous.content}\n\n{message.text}"
    if info:
        previous.additional_info = info     # 引用挂在本轮最后一条上
    continue
```

### 验收

同一个会话：修复前 4 条（1 问 + 3 答），修复后 **2 条**，
合并后 1526 字，**10 条引用完整保留**。

## 三、产品详情里点「咨询顾问」，上下文丢了

### 问题

> "点击咨询顾问后虽然是跳转到顾问咨询页面，但是却没有刚刚点击的保险详情信息的咨询"

### 原因

详情弹窗里的按钮和首页顶部的「让顾问帮我选」共用同一个函数：

```tsx
<Button onClick={consult}>咨询顾问</Button>

function consult() {
  if (session) { onConsult(); return; }   // 只跳转，产品信息丢了
  openAuth(true);
}
```

顾问页进来后从"加载会话列表"开始走，跟刚才看的是哪款产品毫无关系。

### 修法

```
产品详情 →「咨询顾问」
      ↓
未登录？→ 记住这句开场白 → 登录 → 继续
      ↓
/advisor?ask=<开场问题>
      ↓
顾问页：新建会话 → 自动把这句发出去 → 清掉 URL 参数
```

开场白由前端生成：

> 我想咨询「人保小学童2号Pro学平险」这款产品（意外险，中国人保财险），
> 想了解它具体保什么、适合什么人、投保有什么注意事项。

两个实现细节：

1. **`sendContent(content, threadId)` 要显式传线程 id** ——
   新会话刚创建时 `activeThreadId` 这个 state 还没生效（setState 是异步的），
   不传就会把第一句话发到旧会话里
2. **URL 参数只消费一次** —— 发完立刻 `replaceState` 清掉 `ask`，否则刷新会重复提问

## 四、待支付的订单没有出口

### 问题

下单后没付款，订单就一直挂在"待支付"，页面上既不能付也不能取消。

### 修法

**取消**：`POST /api/v1/orders/{id}/cancel`

```java
// 幂等键显式置空：MySQL 唯一索引允许多个 NULL，这样一来
// 用户取消后重新下单（同一方案 + 同一份试算）不会被这张废单挡住。
// 注意不能用 updateById：MyBatis-Plus 默认忽略 null 字段，写不进去
lambdaUpdate()
        .eq(Order::getId, orderId)
        .eq(Order::getStatus, STATUS_PENDING_PAYMENT)
        .set(Order::getStatus, STATUS_CANCELLED)
        .set(Order::getIdempotencyKey, null)
        .update();
```

**继续支付**：复用 `POST /orders/{id}/pay`，但加了一道新校验：

```java
// 待支付订单可能放几天，试算的 24 小时有效期早就过了
if (order.getQuoteIds() != null && !order.getQuoteIds().isEmpty()) {
    PremiumQuoteVO quote = quoteService.getMine(order.getQuoteIds().get(0));
    if (quote.expiresAt().isBefore(LocalDateTime.now())) {
        throw new BadRequestException("试算报价已过期，请重新下单");
    }
}
```

**前端**：订单卡在「待支付」时显示「取消订单」+「去支付」，处理中禁用按钮防连点。

### 验收

```
下单 → pending_payment
取消 → cancelled
重复取消 → cancelled（幂等）
用同一份试算重新下单 → 新订单（幂等键已释放）
支付新订单 → paid
[反例] 取消已支付订单 → 400「订单当前状态为 paid，不能取消」
```

## 五、为什么没做"订单详情页"

订单卡上已经展示了订单号、状态、合计保费、逐项产品和金额 —— 打开详情页看到的
还是同样的内容。**没有新信息的页面只会增加点击成本。**

真正需要详情页的时机是：加物流式的状态时间线、发票、退款记录。现在没有这些，
所以不做。

## 六、四个修复的共同点

| 问题 | 本质 |
|---|---|
| 空表单 | **有界面没数据** —— 点下去什么都不发生 |
| 碎气泡 | **展示层和后端数据形状不一致**（流式拼接 vs 逐条存储） |
| 丢上下文 | **页面间跳转没有携带意图** |
| 订单无出口 | **状态机有状态，界面没有对应动作** |

四个都不是"功能缺失"，而是**功能之间的接缝没接好**。这类问题在面试里比新功能更能体现
"有没有真的用过自己的产品"。
